# 删除会话

在会话行菜单（`⋯` 按钮和右键菜单）里增加一项 **删除会话**，确认后把这个会话的存储目录从磁盘删除，连同它派生出的子智能体会话。

## 安装

1. 把仓库克隆到本地任意位置：

   ```sh
   git clone https://github.com/Lsc-91-69/dsh-session-delete.git
   ```

2. 在 DSH 里打开 **插件 → 添加插件**，选择克隆下来的目录（或调用 `plugin_manager` 工具的 `install_bundle`，传入该绝对路径）。bundle 自带 `cordis.patch.yml`，不需要手动改补丁。
3. 刷新一次 Web UI（`Ctrl+R`），每个会话行的菜单里就会出现这一项。

面向 **DSH 0.2.2-rc.3**（Desktop 版）开发与验证。它使用 Host 的 `connection`、`sessionPersistence` 服务，以及 Client 的 `contextMenus`、`slots`、`locale` 服务；其他 DSH 版本可能需要小幅调整。

## 使用过程

1. 在会话行的 `⋯` 菜单里选 **删除会话**。
2. 确认框会做一次只读预检，显示这个会话的准确存储目录、磁盘占用，以及会一并删除多少个子智能体会话。
3. 点 **永久删除**：
   - **没被打开过的会话**（本次 DSH 运行里没碰过）：目录立刻删掉，侧栏这一行马上消失，不用刷新页面。
   - **正开着、或还有工作没跑完的会话**：DSH 进程里还驻留着它的 Agent，日志也在写句柄里；直接删文件会被它写回来。这时确认框会说明情况，按钮变成 **标记删除，重启后生效**——标记后，下次启动 DSH 时会先清掉它，再加载会话列表。

## 为什么打开过的会话要等重启

DSH 里一个会话只要被打开过，它的 Agent 就会一直驻留到进程退出，并持有日志的写句柄；会话列表又是从内存里的活会话补齐的。所以对这类会话，「删文件」不会让它从列表消失，反而可能被写回磁盘。等重启后它变成普通冷会话，删起来就是干净的一次。

## 其他限制

- **归档会话** 是可逆的做法：只隐藏这一行，保留日志。
- 删除不可恢复，没有回收站，也不能撤销。
- 工作区注册表有自己的成员列表：删除时会把它从置顶和归档集合里移除；剩下那条过期成员记录会被侧栏忽略，因为日志已经不在了。
- 图片和附件是按内容寻址、多个会话共用的，所以不会被删除。
- 待删除队列存在 `~/.dsh/session-delete/pending.json`（若设置了 `DSH_HOME` 则在其下）；删掉这个文件就等于取消所有待删除。

## 停用

在 **插件** 里停用或移除这个 bundle 即可：菜单项和确认框消失，已删除的会话不会恢复，待删除队列也不会再被执行（下次启动不再清扫）。本插件不会发起任何模型请求。
